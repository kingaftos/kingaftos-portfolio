# One launch path: Supabase + Cloudflare Pages

For the currently hosted Netlify shop, use [PROMO_PRICES.md](PROMO_PRICES.md) to install the promo update. This guide describes the original setup. The fresh setup below includes promo prices. After using any of the three original migrations in step 3, also run `supabase/add-promo-prices.sql` to add promo prices.

Complete each numbered step before the next. No custom domain or paid subscription is required initially. You create accounts and enter your passwords directly on the providers' websites. Never paste a password, database password, secret key or service-role key into chat or browser code.

1. **Extract the ZIP and prepare your accounts.** Keep the extracted folder on your PC. Create/sign in to [Supabase](https://supabase.com/dashboard) and [Cloudflare](https://dash.cloudflare.com/). Choose their Free plans. **Result:** you can access both dashboards. GitHub is optional for your own copy; you don't need another ChatGPT plugin.

2. **Create a dedicated Supabase project.** In Supabase choose New project, select your Free organisation, give it a name and strong database password, and choose a suitable nearby available region. Store the password privately. Wait until the project is ready. **Result:** a project with Database, Authentication, Storage and SQL Editor sections. If you already have products in a project, use the migration branch in step 3 instead of creating a replacement without a backup.

3. **Run exactly ONE database script.** Open SQL Editor → New query, paste the whole chosen file and Run. For a new empty project use `supabase/setup.sql`. For the exact supplied Claude schema use `supabase/migrate-claude.sql` INSTEAD. For the earlier ChatGPT schema use `supabase/migrate-chatgpt.sql` INSTEAD. For the installed `Futarian_Home_Deco_Final.zip` schema use `supabase/migrate-final-v2.sql` INSTEAD. Back up existing projects first as described in MAINTENANCE.md. If your schema differs or any query fails, stop; don't run another setup file to guess a fix. **Result:** `products`, `admin_users`, and a PUBLIC `product-images` bucket. Claude imports remain drafts and retain exact originals in `products_claude_backup`; review real stock and prices before publication. Earlier ChatGPT external photo links are preserved in `previous_images` and moved to drafts for reupload. Audit ALL existing bucket photos before this migration: draft photos also become public. Remove any private documents before making the bucket public. Public links and cached copies cannot be recalled. Lighting becomes Lighting & Chandeliers; Mirrors & Decor becomes Mirrors & Art (review décor items manually).

4. **Create and approve your admin.** In Authentication → Users, choose Add user → Create new user, enter your own email and a strong password privately, and confirm the user as the dashboard allows. Copy that user's UUID. In SQL Editor paste `supabase/approve-admin.sql`, replace `PASTE-YOUR-AUTH-USER-UUID` with the copied UUID, and Run. In Authentication → Sign In / Providers, switch OFF “Allow new users to sign up” and keep anonymous sign-ins OFF. Keep email/password sign-in enabled. **Result:** your existing account can log in, but ordinary accounts cannot manage products. Do not create customer accounts.

5. **Enter public configuration.** In your project Connect dialog / Settings → API Keys, copy the project URL and the **publishable** key (or legacy `anon` key). Edit `dist/config.js` in VS Code or a plain-text editor; fill `supabaseUrl` and `supabaseKey` inside the quotes. Set `demo: false`. Confirm the WhatsApp digits are `2348154201739`. Leave social URLs empty until you own real accounts. **Result:** this website uses your database and never substitutes sample products when live loading fails. A public key is expected to be visible; database policies enforce permissions.

6. **Deploy the shop and admin together.** In Cloudflare → Workers & Pages → Create application → Get started → Drag and drop your files (select Pages if the dashboard offers Workers and Pages separately). Name the project, drag in the **dist folder**, and Deploy / Save and Deploy. Upload neither the outer project folder nor the full delivery ZIP. **Result:** a public `https://YOUR-PROJECT.pages.dev` website with `/admin/` on the same address. Supabase does not host these HTML pages. Do not advertise the URL yet.

7. **Set the final URL and business information.** In Supabase Authentication → URL Configuration set Site URL to your pages.dev address and allow that same origin as needed. In `dist/index.html`, change the `og:image` content from `assets/social.jpg` to `https://YOUR-PROJECT.pages.dev/assets/social.jpg` using your actual URL. Add `<link rel="canonical" href="https://YOUR-PROJECT.pages.dev/">` in the head. Review `dist/policies.html`: confirm your delivery areas/fees, handling of faulty and change-of-mind returns, supplier warranties, refund process, custom-item cancellation terms, record retention and delivery-partner information. Do not publish deadlines or promises you cannot honour. The supplied policy deliberately leaves timing and fees to confirmation before payment and does not remove statutory rights. Deploy the updated `dist` again using Create a new deployment → Production. **Result:** accurate business information and an absolute image URL for social sharing.

8. **Add real products.** Visit your public website's `/admin/` address. Sign in using step 4's account. Add product → name, description, category, whole-naira price (or blank for a quote), real stock/order slots, comma-separated tags and up to six photos. Save as Draft first. Reopen it to check the photos and details, then set Published and Save. **Result:** published products appear in a freshly loaded shop, while draft product rows remain admin-only; their photos are public to anyone with the link. If a photo is over 5 MB, resize it first; supported JPG/PNG/WebP uploads are automatically reduced to 1200px. Confirm you have permission to use all product photos. Do not use sample prices as real selling prices.

9. **Run the live checks.** In SQL Editor run `supabase/verify-rls.sql`; expect a PASS result, with fixtures rolled back. Then complete the live checklist in VERIFICATION.md: login, image upload, draft privacy, ordinary-account denial, search plus sorting, cart reload, unavailable stock, and WhatsApp opening on your Redmi 14C. Use a separate signed-out/private browser for the shop. **Result:** both data permissions and the real hosted journey work. A failed check means fix it before advertising.

10. **Launch and keep a backup.** Save the configured project folder and product/photo backups privately. Confirm the WhatsApp account is yours and ready to receive messages. Share the pages.dev address on WhatsApp, Instagram, TikTok and your flyer. **Result:** customers browse without signing in and confirm each purchase with you on WhatsApp. Record agreed orders/payments separately and reduce stock manually after confirming sales. A custom domain is optional later.

## Costs and limits checked on 5 November 2026

| Service | Initial choice | Relevant limits |
|---|---|---|
| Cloudflare Pages | Free plan; free pages.dev address | Dashboard drag-and-drop: 1,000 files, 25 MiB per file. General Free Pages limit: 20,000 files; Git builds 500/month. This buildless site's files are comfortably below these limits. |
| Supabase | Free plan, $0/month | 500 MB database, 1 GB file storage, 5 GB egress plus 5 GB cached egress; up to 2 active free projects. Low-activity projects may pause after a week and require restoring in the dashboard. |
| Domain | Optional | Registrar purchase and annual renewal cost; not included or required. |

Monitor Supabase Usage. If free limits or pausing become unsuitable, its published Pro starting price is $25/month; upgrading is a separate decision, not part of this setup. No paid theme, payment gateway or mandatory plugin subscription is used here.

Official references: [Supabase pricing](https://supabase.com/pricing), [Auth configuration](https://supabase.com/docs/guides/auth/general-configuration), [Storage access](https://supabase.com/docs/guides/storage/security/access-control), [Cloudflare Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/), [Pages limits](https://developers.cloudflare.com/pages/platform/limits/). Dashboard wording can change; the named settings and expected results are the checks to follow.
